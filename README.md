# TOAST JAM — バター対小倉

大きなトースト板に固定したスマホ2台を傾けて遊ぶ、2チームのHTML / JavaScriptゲームです。PC（大型モニター・プロジェクター）1台と、スマホ1〜2台で使います。片方だけの接続でも試遊できます。ビルド・アプリのインストール・APIキー登録は不要です。ユーザー自身のGitHub Pagesで公開できます。

## ファイル

- `index.html`：PCのゲーム画面とスマホの操作画面
- `style.css`：画面デザイン（トーストはCanvasで描画。画像素材不要）
- `app.js`：接続、センサー許可、水平設定、タイマー、結果画面
- `engine.js`：移動と面積の計算
- `tests/engine.test.js`：計算の自動テスト
- `package.json`：テスト実行用。公開するだけならNode.jsも不要

## GitHub Pagesで公開

1. GitHubでリポジトリを作成します。
2. **このフォルダーの中身**をリポジトリ直下にアップロードします（`index.html`が直下に来る形）。既存リポジトリならサブフォルダーに置いても動作します。
3. Settings → Pages → Build and deploymentで「Deploy from a branch」を選び、`main` / `(root)` を保存します。
4. 発行された `https://ユーザー名.github.io/リポジトリ名/` をPCで開きます。反映には時間がかかる場合があります。

GitHub Pagesの公開操作はこの納品には含みません。`file://`で直接開くとJSモジュール・センサーが動作しません。スマホはHTTPSのURLを使ってください。外部ライブラリと接続仲介サービスを使うため、インターネット接続が必要です。

## 最初は板を使わずテスト

1. PCで「キーボード試遊」をチェックします。開始前は具の動きを塗布なしで練習できます。
2. モードと時間を選び「試合スタート」。3秒のカウントダウン後に開始します。
3. バターは **W / A / S / D**、小倉は **矢印キー**。キーから指を離すと摩擦で減速します。
4. 一時停止ボタンまたはSpaceで停止・再開。画面切替でも自動停止します。ボタンや入力欄にフォーカスがあるときは、画面の余白をクリックしてからキー操作してください。
5. 終了後は塗布率と勝敗を表示します。「もう一度あそぶ」で準備画面に戻ります。

## スマホ1〜2台で遊ぶ

1. PCで「接続・QR」。ポップアップ内にチーム別のリンクとQRコードが2つ表示されます。閉じても通信は維持され、再度開いてもQRは変わりません。部屋を新しくする場合だけ「接続用QRを作り直す」を押します。
2. 各チームのQRコードをスマホのカメラで読み取るか、リンクをコピーしてスマホで開きます。QRコードはブラウザ内で生成し、参加URLをQR作成サービスへ送信しません。リンクには部屋・チーム・参加用トークンが入っています。関係者だけに共有してください。
3. スマホに「本体と接続済み」が出るまで待ちます（最大35秒、失敗時は最大2回自動再接続）。通信がつながるまで水平設定はできません。その後「① センサーを許可する」。iPhoneでは許可ダイアログを承認します。Safari、Android Chromeなどで試してください。アプリ内ブラウザではなく通常ブラウザで開くことを勧めます。
4. スマホを水平な板に固定し、上端を画面の奥側に揃えます。両チームで同じ向きにします。「② この姿勢を水平にする」を押します。「水平設定を本体が受信しました。開始できます。」が出ることを確認します。
5. 小さく傾け、右を下げる→右、手前を下げる→下に動くかPC画面で確認します。設置方向によって合わなければ左右／前後の反転を使います。スマホの画面回転をロックすると運用が安定します。v4では画面表示が回転しても水平設定は維持されます。操作の基準は水平設定時のスマホの向きに固定し、表示の回転で前後左右が切り替わらないようにしています。
6. PCでどちらか1チームが「接続・水平設定 OK」になったら開始できます（2台揃っていても開始できます）。開始時点で準備済みのチームだけが参加し、未参加チームは移動も塗布もしません。試合途中で接続・水平設定したチームは、リセット後の次の試合から参加します。スマホ画面には試合の状態と残り秒数が表示されます。スマホ同士にゲーム画面は表示しません。
7. 参加中のチームの通信が3秒以上途切れた場合、明示的な切断、スマホの画面消灯・アプリ切替・緊急停止で試合を一時停止。センサー通知が1秒空いた場合は入力だけゼロにし、水平設定は保持して次の通知で操作に戻ります。画面表示の回転だけでは停止しません。センサー再許可が必要なら許可し、水平設定をやり直してPC側で再開します。再開にも3秒の準備時間があります。

画面消灯を防ぐWake Lockを対応ブラウザで要求しますが、OSや省電力設定で解除されることがあります。自動ロック時間を事前に確認し、充電を確保してください。スマホは画面を開いたままにします。

## 2つのモード

### よこならび

独立した同サイズのトーストで、制限時間内に塗った面積を競います。一度塗った場所を通っても面積は増えません。塗布率の高いチームが勝ちです。端を越えると落下して3秒間操作・塗布できなくなり、開始位置に復帰します。

### 陣取り

共通トーストを塗り合います。相手の色を上塗りでき、終了時点で所有している面積を競います。塗布率の合計は100%以下です。塗っていない部分はどちらの得点にもなりません。塗り手同士は衝突せずすり抜けます。端を越えると落下して3秒間操作・塗布できなくなり、開始位置に復帰します。同じ位置の塗り順は計算ステップごとに交互にし、固定のチーム優先を避けています。

いずれも96×96セルを対象に、半径4セルの円で塗ります。外側の茶色い耳は採点対象外です。塗布率はセル数による近似で小数1桁表示。差が0.05ポイント未満なら引き分け。試合中は60Hzで計算し、PCのゲーム時間を正とします。処理が2秒を超えて中断した場合も停止するため、厳密な実時間ではなく実際に進行した時間で競います。

## リアルタイム同期の仕組みと制限

```
スマホA（バター）── 傾き・水平設定状態を20Hz送信 ──┐
                                                 PC（ホスト）
スマホB（小倉） ── 傾き・水平設定状態を20Hz送信 ──┘
                                      物理計算・塗布率・時間・勝敗を一元管理
```

- **PeerJS 1.5.5 + WebRTC DataChannel**。JSはjsDelivrから取得し、PeerJS Cloudを接続仲介（シグナリング）に利用。GitHub Pages自体は静的ファイルを配るだけです。音声・映像・位置情報は取得しません。
- ゲーム状態はPC内だけで保持し、スマホから正規化した傾きとready状態を送信します。PCから状態・残り時間を約2Hz送ります。端末同士で別々に物理計算しないため、得点の食い違いを避けます。
- 通信チャンネルはWebRTCで暗号化されます。参加URLのランダムトークンを確認し、チームに1台だけ接続を認めます。ただし一般公開イベント向けの厳密な認証ではありません。参加リンクは公開しないでください。
- PCの再読込で部屋と試合は失われます。スマホ切断は「再接続」を使い、PC再読込後は新しい参加リンクを開き直します。
- **接続の成功は保証できません**。会場Wi-FiのUDP制限、端末隔離、NAT、企業ネットワーク等でWebRTCが成立しない場合があります。本構成で専用TURNサーバーは用意していません。公共の接続仲介サービスにも可用性保証はありません。
- 本番前に同じ端末・同じネットワークで必ず接続リハーサルを行ってください。接続不可なら別のWi-Fi等で再確認し、当日の代替としてキーボード試遊を用意してください。大規模・安定運用には自前PeerServerと認証付きTURNの設定や専用WebSocketサーバー等の追加設計が必要です。
- QR表示用のqrcode-generator 1.4.4もjsDelivrから取得します。取得に失敗した場合はQRの代わりに案内を表示し、接続リンクは引き続き利用できます。
- Google Fontsは見た目のためだけに取得し、取得できないと端末のフォントで表示します。PeerJSが取得できない場合もキーボード試遊は動作します。完全オフラインでスマホ間接続する構成ではありません。

## 大型板での安全確認

まず机上、次に手持ち、次に少人数・低い位置の板で確認してから人数や板を大きくしてください。3m角の段ボールはたわむため、スマホ付近の姿勢と板全体の姿勢が一致しないことがあります。センサーだけでは板の変形や参加者の安全は判定できません。

- 軽い板を使い、角と切り口を保護。スマホはケース等で二重に固定し落下しない構造にします。
- 頭上に上げず、身体や首で支えず、低い位置でゆっくり動かします。大きく傾けても入力は約18度相当で頭打ちです。無理に傾ける必要はありません。
- 参加者の足元、周囲の距離、板の下からの退出経路を確保します。板の外に専任の進行役を置き、声の停止合図を共有します。
- 痛み・息苦しさ・ぐらつき・固定の緩みがあれば即停止。画面の停止は板を物理的に止める装置ではありません。板の下の人が無理なく離脱できることを優先してください。

## 開発・調整

ローカル確認は、このフォルダーで `python -m http.server 8000` を実行してPCから `http://localhost:8000` を開きます。LANのHTTPアドレスをスマホで開いてもセンサー許可を得られない場合があります。スマホ試験はGitHub Pages等のHTTPSで行ってください。

Node.jsがある環境では `npm test` で面積・上塗り・傾き変換・境界のテストを実行できます。外部依存のインストールは不要です。調整する場合は `engine.js` の移動加速95、摩擦2.8、塗り半径4、`orientation()` の18度を変更します。

## v3：Negotiation failed の修正と確認

接続処理に、WebRTCの通信確立前から7秒の認証タイマーを開始してしまう問題がありました。通信確立が遅れると接続途中で本体側が切断していました。認証タイマーは通信確立後から10秒に変更しています。また、通信エラーが水平設定の表示で上書きされる問題を直し、通信状態とセンサー状態を別々に表示します。接続失敗時は最大2回自動再接続し、古い試行の遅延イベントが新しい接続を切断しないようにしています。

これはコード側の問題の修正であり、すべての回線で接続できる保証ではありません。`Negotiation of connection ... failed` はWebRTCの接続確立の失敗です。原因はこのメッセージだけでは断定できません。

1. 一式をGitHubへ上書きし、Pages反映後に本体をCtrl+Shift+Rで再読込します。フッターが「v3」であることを確認します。
2. スマホの古い操作画面を閉じ、本体で「スマホを接続する」から新しいQRを発行して読み直します。本体のページは開いたままにします。
3. スマホで「本体と接続済み」→センサー許可→水平設定→「本体が受信しました」の順に進むことを確認します。
4. 同じWi-Fiでも失敗する場合、そのWi-Fiの端末間隔離や通信制限、公開TURNサービスの問題等が考えられます。個別の原因は未確定です。別の家庭用Wi-Fiで試すか、本体をスマホのテザリングに接続し、スマホはモバイル回線を使って切り分けてください（通信量が発生します）。
5. 回線を変えても失敗する場合は、本体／スマホのOS・ブラウザと、通信状態の全文を確認します。管理されたWi-Fiで運用する場合、専用のTURN（TCP/TLS対応）やサーバー中継方式の追加が必要になることがあります。GitHub Pagesだけではその中継サーバーは動かせません。

PeerJS 1.5.5の既定設定には公開STUNと公開TURNが含まれていますが、専用TURNは用意していません。公開サービスの可用性は保証できません。接続先を無関係な無料中継サービスに自動変更する実装はしていません。

- [使用版の既定STUN/TURN設定](https://github.com/peers/peerjs/blob/v1.5.5/lib/util.ts)
- [PeerJS公式：NAT、TURNと接続失敗](https://peerjs.com/client/faq)

v3の自動テスト15件は、接続確立前のタイマー、接続失敗時の表示、再試行の上限、再接続後の状態保護、水平設定の受信表示、ゲーム計算と進行を模擬環境で確認しています。実スマホ2台／利用中のWi-Fiでの接続成功は未検証です。

## v4：意図しない一時停止の修正

旧版は画面回転を検知すると水平設定を解除し、0.8秒センサー通知が空いた場合も解除していました。そのためPCの再開ボタンを押しても、スマホの水平再設定がないと再開できませんでした。v4では以下に変更しています。

- 画面表示が回転しても停止せず、水平設定時のスマホの向きを操作軸として保持。
- センサー通知が1秒空いたときは入力をゼロへ。水平設定は保持し、次の通知で操作が復帰。センサーが実際に停止した場合も、古い傾きで加速し続けません。通知が続かない間は傾けても反応しないため、センサー許可やブラウザの状態を確認してください。
- 通信パケットが0.3秒以上空いた間は入力をゼロにし、3秒以上途切れた場合に試合を停止。接続が明示的に切れた場合はすぐ停止。
- PC側のフォーカスが移っただけではスマホ操作の試合を停止しない。キーボード試遊はフォーカス喪失で停止。PCページが非表示になった場合は両方とも停止。
- 停止理由をスマホにも送信。画面消灯・アプリ切替・緊急停止では安全のため水平再設定が必要。

v4は自動テスト19件に合格しています。90度の画面回転後もreadyと操作軸が維持されること、センサー通知の空白中はゼロ入力で次の通知から復帰すること、緊急停止・非表示・通信切断の停止が残っていることを模擬環境で確認しました。実機での回転・会場通信の確認は必要です。更新後のフッターが **v4** であることをPCで確認し、新しく発行したQRでスマホを開き直してください。

### テザリング以外で接続するには

テザリングで成功し、元の同一Wi-Fiで失敗するという観察から、元のネットワークの端末間隔離やWebRTC通信制限が有力な候補です。ただし、それだけで原因を断定できません。

1. **ゲスト用・来客用SSIDを避け、端末同士が通信できる通常のSSIDへ両方を接続**します。同じSSIDでもAP隔離／クライアント隔離があると通信できないことがあります。
2. 学校・会社・会場のWi-Fiなら、管理者に「イベント用PCとスマホ間のWebRTC通信を許可できるか」「AP／クライアント隔離の対象になっていないか」を確認します。全体の保護を解除するのではなく、許可されたイベント用ネットワークを使います。
3. 別の家庭用Wi-Fiや、会場で利用許可を得た専用ルーターへPCとスマホをまとめる方法もあります。この版はGitHub Pages、PeerJS Cloud、外部ライブラリを使うため、インターネット接続は引き続き必要です。
4. 元のWi-Fi設定を変更できない場合は、**TURN中継（TCP/TLS・443番ポート対応）またはWSSサーバー中継**を追加する方法があります。どちらも別のサーバー／サービスの準備が必要で、GitHub Pagesのファイル更新だけでは用意できません。通信の許可条件によっては中継を用意しても接続できない場合があります。

v4は元のWi-Fiの制限を解消する更新ではなく、自動停止の修正です。専用TURNやWSSサーバーの契約・公開・設定変更は行っていません。

- [TP-Link公式：AP隔離は同一Wi-Fiの端末間通信を止める](https://www.tp-link.com/us/support/faq/2089/)
- [WebRTC公式：TURN中継](https://webrtc.org/getting-started/turn-server)
- [RFC 8835：UDP制限時のTCP/TLS対応](https://www.rfc-editor.org/rfc/rfc8835.html)

## v5：落下・3秒復帰ルール

- 両モードで、塗り手の**中心がパンの塗布範囲（耳の内側の四角形）の端を越えた時点**で落下します。パンの耳は足場に含みません。
- 落下したチームは3秒間、傾き／キーボードで動かせず、塗布もしません。これまで塗った面積は残ります。
- トーストの上にチーム名・「落下！！」・残り「3」「2」「1」を表示します。陣取りモードでは共通トースト上に2チーム分を左右に分けて表示し、同時落下にも対応します。
- 3秒後、両チームともトーストの中央へ、速度ゼロで復帰します。復帰後は現在の傾き／キー入力が再び有効になります。落下中に水平設定をやり直す必要はありません。
- 相手の操作と試合タイマーは進みます。全体を一時停止した場合は、落下からの復帰カウントも停止し、全体の再開後に進みます。試合終了時は復帰待ちでもその時点の塗布率で勝敗を決めます。

v5は自動テスト29件に合格しています。四辺からの落下、両モードでの3秒間の操作／塗布禁止、復帰位置と速度、相手の試合続行、落下表示と3→2→1、全体停止中のカウント保持を模擬環境で確認しています。実機の表示・操作は公開先で確認してください。更新後のフッターは **v5** です。

### テザリング構成の確認

このゲームは、PCと2台のコントローラースマホが必ず同じWi-Fiである必要はありません。それぞれがインターネットに接続し、WebRTCの通信が成立すれば、異なる回線でも使えます。ただし利用回線の制限によって成立しないことがあります。

今回成功した方法を2チームで使うなら、次の構成が候補です。元のスマホとPCでの成功は確認されていますが、もう1台を含めた3台構成は会場で確認してください。

```
スマホA：モバイル回線＋テザリングON＋バターのコントローラー
  ├─ PC：Aのテザリングに接続し、本体画面を開く
  └─ スマホB：Aのテザリングに接続し、小倉のコントローラー
```

テザリング元のスマホAもコントローラーに使うため、別の通信用スマホを追加する必要はありません。スマホBを独自のモバイル回線にした構成も接続できる可能性がありますが、事前検証が必要です。どちらの構成でもPCとスマホは同じPCが発行したQR／リンクを使ってください。

v5では通信方式とv4の自動停止条件は変更していません。まだ起きている一時停止については、PCのスタートボタン付近に出る停止理由とスマホ側の表示を確認してください。通信切断・画面非表示・緊急停止・PC処理の2秒を超える中断等を区別できます。

### コンフィグ

準備中に「コンフィグ」を開き、スライダーで両チーム共通の係数を設定します。設定はそのページを開いている間、リセットや再試合でも維持します。再読み込みすると標準値へ戻ります。試合中・一時停止中・結果表示中は変更できません。「リセット」して準備中へ戻ってから変更します。

| 項目 | 標準 | 範囲 | 動作 |
|---|---:|---:|---|
| 全体の摩擦係数 | 2.8 | 0.2〜12 | すべての場所で速度を減衰。大きいほど滑りにくい |
| パン周辺の追加摩擦係数 | 8.0 | 0〜30 | 外周12セル（幅の12.5%）で端へ近づくほど全体摩擦に加算。0で追加なし |

これはゲーム用の速度減衰係数で、実物の素材の摩擦係数を再現するものではありません。追加摩擦を大きくしても、傾け続けたり速度が大きいと落下します。「標準に戻す」で上記の値へ戻せます。

### 開始前の操作確認
